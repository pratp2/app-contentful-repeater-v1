# Security Policy

## Supported Versions

Security updates are applied to the latest stable release. We encourage upgrading to the newest version.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |

If you are using an older release, please plan an upgrade to a supported version.

## Reporting a Vulnerability

If you believe you have found a security vulnerability, please report it responsibly.

**Do not** open a public GitHub issue for security-sensitive bugs.

**Preferred:**

- Email the maintainer(s) (e.g. the author listed in [package.json](package.json) or README) with a clear description of the issue, steps to reproduce, and impact if possible.
- If you have a PGP key, you may encrypt the message.

**What to expect:**

- We will acknowledge receipt and aim to respond within 5 business days and provide a remediation plan or timeline.
- We will work with you to understand and address the issue and will keep you updated on progress and any fix/release plan.
- We will credit you in the fix/release notes (unless you prefer to remain anonymous).

Contact: send an encrypted message (PGP) or email to the project maintainer listed in `package.json`. If you do not have a PGP key, use the maintainer's public email with a reasonable level of detail (do not include secrets).

Thank you for helping keep this project and its users safe.
